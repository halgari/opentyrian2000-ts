# Game Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the full single-player game playable in the browser, frame-exact against the C oracle: new game, episode scripts, shop, real input, save/load, death and restore, and episode end.

**Architecture:** New screens and game modules ported 1:1 from `tyrian2.c`, `game_menu.c`, `mainint.c`, `menus.c`, `config.c`, `backgrnd.c` and `animlib.c`. Verification comes from an extended oracle (key holds, mouse, extended state, save dumps), synthetic demos covering every level, and scripted session goldens.

**Tech Stack:** TypeScript, vitest, the existing modules, and the C oracle patch.

**Spec:** `docs/superpowers/specs/2026-10-09-gameflow-design.md`.
**Survey:** `docs/superpowers/specs/2026-10-09-gameflow-survey.md`. Every task names the survey sections to read. The previous survey, `2026-10-09-gameplay-survey.md`, still applies.

## Global Constraints

- **C source:** `reference/opentyrian2000/src/`, commit `aad5aca01af139c0b089237c38ef765f7a84355d`.
  - Read each C function **in full** before porting it.
  - Mark every port with `// port of <fn> (<file>.c)`.
- **File headers:** copy the 5-line copyright/SPDX header and the `// Ported from:` line from existing files such as `src/game/level.ts`.
- **State:** no module-level mutable state.
  - Game state lives in `ctx.game` (`src/game/world.ts`).
  - Screen-local state lives in locals or in per-call state objects, the way `LevelLocals` does.
  - Strings the C mutates at runtime (`menuInt`, …) live per-ctx, not in shared constants.
- **C semantics:**
  - Use integer widths from `src/core/int.ts`.
  - Use `cmath.ts` for float32 math, `roundf32` and `rngMod`.
  - Keep the scratch globals (`g.scratch.temp/temp2/temp3/tempW/b/x/y`) faithful, including writes from shop and menu code, because later code reads their stale values (survey §7.11).
  - Draw random numbers in the C's exact call order. GCC evaluates function arguments right to left, so for `f(mt_rand()%a, mt_rand()%b)` the **second** argument is drawn first.
- **Unported branches** (two-player, galaga, arcade, network, joystick, editor ship, debug keys) are marked `// TODO(sp5): <C ref>` and throw `unported:` if reached.
- **Platform:** browser-only code goes in `src/platform/` or `src/main.ts`. Game logic never touches the DOM.
- **Tests:**
  - Write the tests first.
  - Goldens skip when their oracle files are absent.
  - Never write debug dumps over fixture files; use `--raw` (`.dbg.frames`), not `--fixture`.
- **Parallel waves:** other agents may be working in the same checkout.
  - Run your own test files plus `pnpm typecheck`, and note breakage in other agents' areas without fixing it.
  - `git add` only your own files.
  - Never use git stash, reset or checkout on files that aren't yours.
- **Commits:** messages end with `Claude-Session: https://claude.ai/code/session_01JXJ4hjEXrGM5Vja2B6e4Wz`.

## Review Focus

1. **Browser keys conflicting with game keys:** Alt focusing the menu bar, Space/arrows scrolling the page, and Esc ending pointer lock. Covered by Task 6 tests on `dom-input` with synthetic events.
2. **A corrupt or foreign save in localStorage:** the C `exit(255)`s on a bad checksum. The TS must instead warn, show the defaults, and keep the corrupt blob under a backup key without losing it (Task 5 test).
3. **The tab losing focus mid-level:** the game must pause like the C's `!windowHasFocus` path and resume on a key or click (Task 6 test).
4. **Starting a new game after a game over, or after quitting to the title, without a reload:** no world state may leak (Task 12 test that runs two sessions back to back in one ctx and compares them to fresh-ctx runs).
5. **Storage quota or a blocked localStorage** (private mode): the game runs with in-memory saves and a console warning (Task 5 test).

### Task 1: Oracle v2
**Read:** survey §6 and §8 item 1.
**Files:** `tools/oracle/dump-frames.patch` (regenerate as before, from an edited `reference/oracle` tree with `git diff`), `tools/oracle/run.ts`, `tools/oracle/scenarios.ts`, `tools/oracle/discover.ts` (new), `test/helpers/state-trace.ts` (adds STATE2), `README.md`.
**Produces:**
- **Key and mouse injection:**
  - `OT_KEYS` entries `frame:sc[:hold]`: keydown after frame f, keyup after frame f+hold. Hold 0 means a tap, as now.
  - `OT_MOUSE` entries `frame:type:a:b`: `m:dx:dy` relative motion, `d:btn` button down, `u:btn` button up.
  - Injection must also fire from the delay or poll hook when no frame is presented for N polls (`OT_IDLE_POLLS`, default 50). The index is then the last presented frame. This lets keys reach blocking screens. Document the exact rule.
- **`OT_STATE2`:** a v2 record, as fixed-size LE u32/s32 fields in a documented order: frame, mtCalls, cash (low 32 bits), front power, rear power, items[12], mainLevel, nextLevel, saveLevel, episodeNum, difficultyLevel, levelEnd, endLevel, reallyEndLevel, gameLoaded, curMenu, lvlFileNum, armor, shield, the scratch values temp/temp2/temp3/tempW, and p0 x/y.
- **Save dumps and seeding:**
  - `OT_SAVEDUMP=dir` copies HOME's `tyrian.sav` and `tyrian.cfg` there at exit, including on `OT_MAX_FRAMES` exit.
  - `run.ts` supports `homeSeed: path` (copy a sav into HOME before the run) and `dataDir: path` (alternate data dir).
- **Scenario shape:** scenarios gain `keys` with holds, `mouse`, `state2`, `saveDump`, `homeSeed` and `dataDir`.
- **Discovery:** `discover.ts` takes a scenario prefix and a list of intended inputs ("Return when the next screen is idle"). It runs the oracle repeatedly, reads the hash file, and finds the frame at which each screen becomes idle (the last frame before blocking). It writes a concrete scenario to `scenarios.ts`.
- **First scenario:** `newgame-ep1-first-shop-to-level`. It goes title → New Game → episode 1 → difficulty normal → shop → Next Level → planet → level 1, holding fire and moving for about 300 frames, then exits. It records hash, STATE2 and savedump.
**Tests:**
- Existing goldens unchanged: boot, menu-nav, demo-1..5, demo-abort.
- STATE2 reader unit test.
- Running the oracle twice gives identical outputs for the new scenario.
**Commit:** `feat(oracle): v2 — holds, mouse, STATE2, save dump, discovery runner`.
